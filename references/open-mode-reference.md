# Open Mode Reference

## 目的

定义 open mode 的最小约束，供复杂请求或未命中标准能力的请求使用。

## 输入

只接收 `route.type = "open"` 的当前 task。

## 回答原则

默认中文、结构优先、只围绕当前 task 展开；先回答核心问题，再给必要结构。

## 产物规则

默认不落盘，不默认生成 Canvas；除非用户明确要求，否则只输出语言回答。

用户明确要求保存时，open mode 只允许新建文件，不允许删除、移动、修改或覆盖已有文件。目标文件已存在时必须停止并说明原因，不得自动改名写入，也不得设置覆盖。

允许新建的轻量产物：

| 类型 | 位置 | 最小规则 |
|---|---|---|
| Markdown | 用户确认的 Vault 内 | 使用 Obsidian `[[概念]]` 链接，结构清楚，概念只选重点 |
| Canvas | `10_Maps/*.canvas` | 使用 Obsidian `[[概念]]` 文本节点；线条少，关系优先写进节点文字，只画关键边 |

## 限制

不调用标准 py，不伪装标准产物；概念只选重点，不铺开百科。open mode 生成文件时只能使用安全新建，不得覆盖已有路径。

## 不负责

不负责标准命令分流，不展开 py 细节，不讨论未来功能规划，也不把未实现能力伪装成标准流程。

## 下一步

若生成了文件产物，先读 `references/runtime-check.md`；回答结束前一律读 `references/quality-check.md`。如果队列里还有其他 task，由 `references/route-reference.md` 继续推进。
