# Text Output Reference

## 目的

统一格式化文件 task 的用户可见回执。本文档不生成文件、不判断 route、不修改任务结果，也不规范纯语言回答的内容。

## 何时读取

满足以下任一条件时，在全部 task 执行结束后读取：

- 队列包含已通过 `references/runtime-check.md` 的文件产物；
- 队列包含 `operation.action = "keep"` 的 task；
- 文件 task 执行失败，需要给出准确失败回执。

纯 `answer` 队列不得读取本文件，直接把 open route 形成的语言回答交给 `references/quality-check.md`。

## 文件回执

| action 与结果 | 输出格式 |
|---|---|
| `create` 成功 | `已使用 <能力> 生成：<绝对路径>` |
| `update` 成功 | `已使用 <能力> 更新：<绝对路径>` |
| `keep` | `已保留原文件，不进行修改：<绝对路径>` |
| 执行失败 | `未生成或更新文件：<明确原因>` |

只有脚本 result 和 Runtime Check 都成功时，才能使用“已生成”或“已更新”。路径必须来自本次实际结果或已经确认的 keep 目标。

## 混合队列合并

每个 task 先独立形成结果，再按 `task_queue[].id` 原顺序合并：

- `answer`：使用 open route 已经形成的语言回答片段，保持原意，不由本文件重写、压缩或增加机械前缀。
- `create` / `update` / `keep`：使用本文件规定的文件回执。
- 连续多个文件回执可以合并为编号列表，但不得改变 task 顺序。

不固定要求“先回答、后列文件”。用户顺序与 `task_queue[].id` 才是唯一排序依据。

## 内容提醒

字数或布局偏重不阻断生成，不自动压缩，不要求用户在生成前选择。任务成功后可在对应文件回执后追加一条短提醒。

中英文分别估算：中文按汉字及全角字符计数，英文按单词计数；混合文本分别统计，任一项达到对应条件即可提醒。以下都是软判断，不是生成上限：

| 产物 | 偏重参考 |
|---|---|
| Canvas 单个核心节点 | 中文超过约 250 字，或英文超过约 130 词 |
| 整张 Canvas | 中文超过约 1000 字，或英文超过约 500 词 |
| Canvas 布局 | group 宽高比低于约 `0.9`，或核心节点高度超过约 `520px` |
| Canvas 接近文档 | group 宽高比低于约 `0.6` |
| Markdown | 中文超过约 1000 字，或英文超过约 500 词 |

数字只辅助判断。内容适合当前媒介时可以不提醒；明显难以浏览时即使未达到数字也可以提醒。

| 情况 | 提醒 |
|---|---|
| Canvas 内容密集、明显偏纵向 | `提示：这张 Canvas 内容较密，已经接近纵向文档；可用“压缩当前 Canvas”覆盖原文件。` |
| Markdown 正文明显过长 | `提示：这份文档内容较长；可要求压缩当前文档或拆分主题。` |

提醒只描述已经观察到的问题，不主动扩展学习主题，不增加新的相关概念或任务清单。

## 多任务示例

以下示例假定两个文件 task 的顺序依次为更新 Compare Canvas、生成 Question Note：

```text
已完成：
1. 已使用 compare_canvas 更新：<绝对路径>
2. 已使用 question_note 生成：<绝对路径>

提示：第一张 Canvas 内容较密，已经接近纵向文档。
```

示例只规定文件回执及提醒格式。混合队列中的 `answer` 仍使用 open route 已形成的回答片段，并按自身 task 顺序插入，不套用上述文件回执句式。
